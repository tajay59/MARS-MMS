# Findings: where the planning documents and browser reality differ

Found while building this skill (2026-10-16). Each needs a decision by the user. When one is decided, update the named documents in the same change (CLAUDE.md), then mark it **Decided** here with the date. Don't silently implement a proposal.

| # | Finding | Evidence | Proposal | Documents | Decide by |
|---|---|---|---|---|---|
| F1 | **OSM tiles and offline use.** The OSM policy says "Offline use is not permitted on tile.openstreetmap.org" and asks caches to honour `Cache-Control`, `Expires` and `ETag`. TRD §13.3 caches viewed tiles cache-first for 30 days, which ignores the ~6-day `max-age` and keeps maps working offline | [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/), response headers checked 2026-10-16 | Option A: let the browser HTTP cache handle tiles (no worker route); maps are online-only, which OFF-10 allows. Option B: keep a worker cache but with `maxAgeSeconds` ≤ the server's max-age and no offline promise. Option C: a tile provider that allows offline use, or self-hosted tiles (T1 fallback) | TRD §13.3, §15 (CSP), T1 | Phase 2 (map) |
| F2 | **iOS keeps the installed app's storage separate from Safari's.** Work prepared in a Safari tab is invisible to the Home Screen app, and Safari tabs are subject to the 7-day deletion rule | [firt.dev](https://firt.dev/notes/pwa-ios/), [WebKit](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/) | On iOS, **Prepare for field** in a browser tab shows the install steps and does not prepare. Install becomes a step of J5 for iPhone users | AFD J5, §6; PRD OFF-1 note; TRD R4 | Phase 5 (W13) |
| F3 | **`persist()` may return `false` in Safari** (WebKit bug 271401, open). R4's first mitigation may not take effect | [Bug 271401](https://bugs.webkit.org/show_bug.cgi?id=271401), [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/) | Test on the iPhone in Phase 0. Show the persisted state on `/sync`; rely on installing and syncing early | TRD §7.1, R4; IP W13 | Phase 0 |
| F4 | **Hashing a 200 MB video.** TRD §7.5 uses Web Crypto for SHA-256, but `crypto.subtle.digest` takes the whole file in memory, risky on iPhones. Wasm hashers are blocked by the CSP (no `'wasm-unsafe-eval'`) | MDN SubtleCrypto; TRD §15 | Pure-JS incremental SHA-256 (e.g. `@noble/hashes`) over `Blob.slice()` chunks in a Worker; or keep Web Crypto and prove it in W13 with a 200 MB file | TRD §7.5, §3.3 (`/uploads` takes `sha256`) | Phase 4 |
| F5 | **The worker arrives late.** IP puts vite-plugin-pwa in Phase 5, so update flow, Nginx headers, CSP for workers and the precache budget are first exercised in W13 | IP Phase 5 | Add the minimal worker and manifest in Phase 1 (no tiles, no Background Sync) | IP Phase 1, 5 | **Decided 2026-10-17: adopted.** Minimal worker and manifest in W4. The update prompt is tested between two releases on the local stack (`e2e/update.spec.ts`); the same check on staging and on a real iPhone and Android phone waits for the staging host (issue #4) |
| F6 | **Playwright's service-worker support is Chromium-only.** TP plans offline tests with the real worker in Chromium and WebKit | [Playwright docs](https://playwright.dev/docs/service-workers) | Prove WebKit behaviour in W14; if it fails, WebKit runs the offline flow without the worker (Dexie only) and the iPhone is the only full check | TP "Offline sync", "Tests by phase" | Phase 5 (W14) |
| F7 | **Lighthouse's PWA testing is deprecated.** Nothing in the docs depends on it; noted so nobody adds it | [Lighthouse PWA](https://developer.chrome.com/docs/lighthouse/pwa) | Use DevTools' Manifest pane and Playwright checks | — (information only) | — |
| F8 | **Queued ops outlive app versions.** Ops may wait days, through app and server updates. TRD §7.2 has no payload version | Expert rule | Each op carries `v`; `/sync` accepts the current and previous versions; Dexie upgrades never reshape queued ops | TRD §7.2, §7.3 | Phase 5 |
